# Saved numeric field review v1

This candidate compares one explicitly selected report number with one saved Evidence table field under declared decimal HALF-UP rounding. It is an analyst review attachment, not factual source certification, a whole-sentence verdict, a report-wide score, an indicator recomputation or a prediction evaluation. The broader professional-product objective remains open.

The frozen [policy](contracts/numeric_review_policy_v1.json) is normative. Its SHA-256 uses the existing sorted-key canonical JSON convention. Implementations must use original saved JSON number lexemes, bounded decimal arithmetic and no epsilon. HALF-UP ties go away from zero. Rounded zero is positive; the original signed source lexeme is retained.

## Frozen report authority

New completed runs produce `ReportTextSnapshotV1` after final Evidence and citation processing and successful Memory completion. It has exactly `schema_version: 1`, `run_id`, `instrument`, `analysis_date`, `captured_at` (actual UTC with exactly six fractional digits and `Z`), `evidence_bundle_sha256`, `report_sections` and `snapshot_sha256`. The hash covers every other field. Configured secrets are redacted before publication and citation processing; the snapshot then retains those exact published strings/nulls. No subsequent trimming, redaction, Unicode or newline normalization is permitted. The standard seven report section keys are present, with null for absent sections.

One immutable snapshot body is permitted per run UUID across retained tasks and versions. Saved native state and the browser ordinary-save prior state enforce this authority; a freshly recalculated self-hash cannot authorize replacing an existing snapshot. Explicit whole-task deletion/clear may remove unreferenced report attachments; no browser tombstone retains deleted report text. The Python run cache separately retains its original per-run capture for completion retries. Legacy versions without a completion snapshot remain explicitly unreviewable. A snapshot is evidence of captured local report content, not provider authenticity or protection against an attacker rewriting every local authority.

## Review wire contract

Each `NumericReviewV1` has exactly these fields:

- `schema_version: 1`, `review_id` (UUID), `reviewed_at` (actual UTC with exactly six fractional digits and `Z`), `previous_review_sha256` (null or prior attachment hash), `policy_version`, `policy_sha256`, `scope: "selected_saved_numeric_field"`.
- `target`: `task_id`, `version_id`, `run_id`, `report_snapshot_sha256`, `section_key`, `section_utf8_sha256` (SHA-256 of raw UTF-8 section bytes).
- `numeric_span`: `start_byte`, `end_byte`, `text`. It is a half-open UTF-8 span of the exact raw section. The selection must cover a complete supported ASCII numeric token. Partial sign/digit/exponent selections and grouped, localized or scaled forms are not comparable. An incorrect byte/text binding is invalid.
- `operand`: `evidence_id`, `source_index`, `provider`, `data_sha256`, `selector`, `raw_number_lexeme`. Provider and lexeme are derived. The artifact hash is null only when this source has no saved normalized-data hash; the lexeme is null when no eligible supported numeric field is available. A broken nonnull artifact reference is invalid. The selector has exactly `kind: "table_cell"`, `table_path` (one of the policy's paths), `row_date` (exact original Date label), and `field` (unique column name). No scalar, formula, conversion or multiple-operand operation is supported by v1.
- `rounding`: `mode: "saved_decimal_half_up"`, `places` (0–18).
- `context_bindings`: `instrument`, `row_date`, `units`, each null or a span with `start_byte`, `end_byte`, `text`. Only exact bound literal comparison is supported. Instrument compares to the frozen requested identity; date compares to the saved local Date label's ISO calendar-date component; units compare to the source's exact saved units string. Unknown units stay unknown. Context selection does not prove independent issuer resolution, exchange-calendar validity or historical availability.
- `result`: `status` (`match`, `mismatch`, `missing`, `manual_inference`), `reason`, `rounded_decimal` (string/null), `context_results` (each `unreviewed`, `match`, `mismatch`, `missing`), `unreviewed_dimensions`, and `source_context` (`instrument`, `row_date`, `units`, `provider`, `historical_availability`, `adjustments`, `transformations`). Decimal results and original number lexemes are strings; they must not pass through binary floating-point arithmetic.
- `review_sha256`: canonical hash of all other fields.

Python, TypeScript and Rust rederive every result, source lexeme and source-context field from the same frozen snapshot/Evidence. A forged match with recomputed hashes is rejected. The reference reason vocabulary and complete example receipts are frozen in shared fixtures before integration.

`source_context.row_date` is null until a unique selected source row is found. Its instrument is the frozen requested run identity, and the selected record's run-identity field must agree. This literal check does not validate effective tool parameters, ticker aliases or the provider's resolved entity. A contrary saved `parameters.symbol` can therefore coexist with a requested-identity literal match; inspect the complete Evidence parameters separately. Effective source identity checking remains open. Other metadata retains the selected source's nullable values. `unreviewed_dimensions` starts with the policy's fixed ordered list, followed by `instrument`, `row_date`, `units` in that order when their context result is unreviewed or missing. Task/version IDs are bounded nonempty strings; run/review IDs are canonical UUIDs.

The reason vocabulary is `value_match`, `value_mismatch`, `context_mismatch`, `context_missing`, `source_unavailable`, `source_withheld`, `table_missing`, `table_ambiguous`, `row_missing`, `row_ambiguous`, `field_missing`, `field_not_numeric`, `number_unsupported`, `selection_unsupported`. Reason precedence is context disagreement, comparable numerical disagreement, missing bound context, unavailable/missing source field, unsupported report selection, unsupported number, then a scoped value match. Source metadata alone may establish literal instrument/unit agreement; withheld or unavailable source data never supplies a numerical match or an observed row date.

Supported saved Date labels contain a valid `YYYY-MM-DD` followed optionally by `T` or a space, valid `HH:MM:SS`, an optional 1–9 digit fraction, and an optional `Z` or signed `HH:MM` offset. Offsets are bounded by ±14:00; the unspecified `-00:00` offset is unsupported. Validation does not normalize or convert the saved local label, and context comparison uses its original calendar-date component. This rule does not establish an exchange session or completed trading day.

Whole-number boundaries explicitly guard partial signs/exponents, adjacent Unicode number characters, leading decimal symbols `.`, `٫`, `．`, numeric-neighbor separators `.`, `,`, `٫`, `٬`, `．`, `，` and nonbreaking/narrow/thin spaces. Scale suffixes guard `%`, `‰`, `‱`, `％`, `٪`, `千`, `万`, `亿`, `萬`, `億`, `兆` and the bounded ASCII k/m/b/t/bp/bps/million/billion/trillion forms. Adjacent localized signs include `−`, `﹣`, `－`, `＋`, `﹢` and `±`. Ordinary `125.02元` can compare only its explicitly selected numeric token, with unbound units still unreviewed. These explicit syntax checks are not universal locale or semantic claim recognition.

Frontend fields are `reportTextSnapshot` on completed tasks/versions, `numericReviews` on versions only, and optional `numericValidation: {status: "invalid", reason}`. Its reason is one of `malformed`, `hash_mismatch`, `reference_mismatch`, `unsafe_content`, `verification_unavailable`. Completed events forward `reportTextSnapshot` and `finalState.report_text_snapshot`; when both are present they must agree. New runs clear the previous current snapshot/validation along with their other run inputs.

## Scope and result behavior

An explicit numerical or context disagreement makes the combined result `mismatch`. Missing selected source/row/field or an asserted unknown context makes it `missing`. Unsupported selections or saved numeric representations give `manual_inference`. Otherwise the selected number can `match`, with every unbound context still listed as unreviewed. The fixed unreviewed dimensions always remain visible, including surrounding prose, source reliability, historical vintage, indicator method, predictions and causality. Source-picker choices never establish what surrounding prose says.

The chosen artifact must belong to that exact Evidence record/source. Withheld or unavailable sources cannot provide a match. Tables require unique column names and unique Date labels; ambiguous fields or dates cannot be silently selected by convenient index. Missing/null/boolean values cannot be converted to zero. Source timestamps, units, adjustment metadata and transformations retain their saved meanings.

## Persistence and exports

Reviews append to `ReportVersion.numericReviews`; the original version core and snapshot are immutable. Identical attachments are idempotent. Rebinding a review UUID or run UUID, rewriting a prior attachment, removing retained review history or stale writes that discard an attachment fail. Explicit whole-task clear/delete remains supported. Browser ordinary saves and native transactions compare prior retained authority, rather than trusting only incoming self-hashes.

Selected-version JSON, HTML and Markdown retain unchanged report sections, complete Evidence payload strings, the frozen snapshot and the full review history/appendix. They rederive reviews against the captured selected version before export. Invalid attachments block export; valid mismatch/missing/manual results remain visible. No green report-wide certification is displayed.

## Required acceptance

Check independent decimal boundaries (`1.005`→`1.01`, `2.675`→`2.68`, negative ties, carries, scientific notation and signed zero), exact Unicode/emoji/combining-mark/CRLF spans, whole-token rejection, wrong bound instrument/date and unknown units. Check missing/withheld data, duplicate rows/columns, cross-record artifacts, edited original sections, coherent rehash attacks, cross-version/run conflicts and stale saves. Exercise actual browser selection, append/save/reload/version switch, JSON/HTML/Markdown downloads and native SQLite migration/reload. No provider or model request is necessary for this feature.
