The implementation atomically reserves an unstarted owner and returns a runtime-unique run ID before any analysis process can start. The frontend subscribes to `analysis-event:${taskId}:${runId}` and then starts that exact owner. Unstarted reservations have a 30-second lease checked on control calls; a claimed owner does not expire. Preparing, running and incomplete cleanup retain admission until known cleanup has been confirmed. Old stop requests, event callbacks and finally blocks cannot retire a replacement owner through task ID alone.

The neutral process owner shares containment with existing probe/inventory code. Unix uses a retained `/bin/cat` group leader and its open input rather than a fixed-duration sleep anchor. Windows creates the runner suspended, assigns the job and then resumes its primary thread. Termination submission, direct-child reaping, anchor/job finalization and completed cleanup are separate steps. Success confirms containment termination submission, known owned handle reaping and analysis output-reader completion; it does not assert that every arbitrary descendant has been observed exiting. Escaped processes, application shutdown and cross-session recovery require separate acceptance. Probe/inventory partial-spawn cleanup uses bounded cleanup and a Drop fallback; it is not proof that every process always ended.

The analysis worker attaches process ownership before writing payload input and retains output-reader handles. Cancelled preparation, blocked/closed input, normal parent exit, reader failures, worker panic and incomplete cleanup use the same owner. Cleanup failures keep the slot for explicit retry. Repeated finish calls inspect actual cleanup rather than only worker retirement. A worker join error checks the exact old owner to return the stable machine cleanup code when ownership remains; a new owner of the same task is not that witness. Desktop task deletion rejects an active owner of the same task and serializes the idle check with storage deletion.

The queue shows stopping until acknowledgement. A cleanup failure keeps the owner, exposes a localized retry button and pauses subsequent dispatch. Five-second frontend waiting windows present unconfirmed cleanup as a failure; they do not guarantee that OS work or IPC completes in five seconds. Retry waits on an already pending stop acknowledgement rather than issuing another unknown stop command. Late reservation acknowledgements are stopped with their own run ID and never started. Late listener acknowledgements are disposed. The session map and queue blocker are in memory; page reload/frontend remount recovery is not implemented or proven.
